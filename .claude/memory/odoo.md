**VERIFIED (2026-07-24, source: direct user statement) — [ADR-0016](../../docs/decisions/ADR-0016-remove-dynamics-crm-eta-platform-extends-odoo.md)** — Odoo's place in ETA's target architecture, as a formal decision, not just a discovered fact: **Website → ETA Platform → Odoo ERP**. No standalone CRM, no ongoing Dynamics integration — legacy Dynamics data (if any) migrates once into Odoo, then Dynamics is retired. **The ETA Platform extends Odoo rather than replacing it.** Odoo is the declared single source of truth for Sales, Purchase, Inventory, Accounting, Contacts, Documents, Projects, Helpdesk, and Approvals.

**RESOLVED (2026-07-24) — [ADR-0017](../../docs/decisions/ADR-0017-single-source-of-truth-odoo.md), implemented same day.** The tension above is settled: Odoo is authoritative. `domains/procurement-core` and `domains/suppliers` no longer have their own Postgres persistence — `PostgresPurchaseOrderRepository`/`PostgresSupplierRepository` and their migrations were deleted, replaced by `OdooPurchaseOrderRepository`/`OdooSupplierRepository` (new `platform/odoo` package, `@eta/odoo-client`), implementing the same repository ports against `purchase.order`/`res.partner` directly. Domain/application layers untouched — only the adapter changed, exactly as hexagonal architecture is supposed to allow.

**New prerequisite, not yet done:** the real Odoo environment needs custom fields added (`x_eta_id` on `purchase.order` and `res.partner`, plus `x_eta_status`/`x_eta_category`/`x_eta_certifications` on `res.partner`) before this code runs live. Implemented and unit-tested (`npx vitest run` — 30 tests passing; `npx tsc --build apps/bff/tsconfig.json` — clean), not live-verified. Any future domain (Inventory, Accounting, Documents, Projects, Helpdesk, Approvals) should default to this same Odoo-backed pattern per ADR-0017, not Postgres.
